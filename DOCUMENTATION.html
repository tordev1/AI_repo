03 AI Component 1: Search-Based Planner

File: ai/search_planner.py
Purpose: Generate an optimal weekly study schedule by allocating subjects across 7 days.

Problem Formulation

State

A partially filled weekly schedule
{ Monday: [(AI, 2h)], Tuesday: [], ... }

Actions

Allocate 1 hour of a subject to any day with remaining capacity

Goal State

All subjects have their required weekly hours fully allocated

Cost

Each allocation has a cost adjusted by subject urgency score

Heuristic Function

h(state) = SUM over all subjects:
              hours_remaining × (1 + urgency_score)

urgency_score = 0.6 × deadline_factor + 0.4 × difficulty_factor

where:
  deadline_factor  = max(0, 10 - days_to_deadline) / 10   // 0 to 1, closer = higher
  difficulty_factor = difficulty / 10                       // 0 to 1

Subjects with closer deadlines and higher difficulty get prioritised — they are scheduled on earlier days of the week.

Algorithm Comparison

PropertyA* SearchGreedy Best-First
Evaluation functionf(n) = g(n) + h(n)f(n) = h(n) only
Considers path cost?Yes — g(n) = cost so farNo — ignores past cost
Optimal?Yes (with admissible heuristic)No (can get stuck)
Complete?YesNot guaranteed
SpeedSlower (more careful)Faster (greedy choices)

04 AI Component 2: Rule-Based Expert System

File: ai/rule_engine.py
Purpose: Assess risk level and generate recommendations using IF-THEN rules with forward and backward chaining.

Forward Chaining (Data-Driven)

Starts with known facts and fires rules to derive new facts until no more rules apply.

Input Facts

stress=8.5, confidence=3.0, deadline=4, workload=5, study=8h

↓ R1 fires: stress ≥ 8

+ stress_level = "very_high", burnout_risk = true

↓ R5 fires: confidence ≤ 3

+ confidence_level = "very_low", needs_encouragement = true

↓ R17 fires: high stress + low confidence

risk_flag = "HIGH"

+ "Seek academic support and reduce workload"

Backward Chaining (Goal-Driven)

Starts with a goal (e.g., "Why is risk HIGH?") and traces back to find which facts caused it.

GOAL: Why is risk_flag = "high"? | +-- Found Rule R17: concludes risk_flag = "high" Conditions: stress_level in (very_high, high) AND confidence_level in (very_low, low) | +-- Why is stress_level = "very_high"? | Rule R1: stress ≥ 8 | Answer: because stress = 8.5 ← BASE FACT | +-- Why is confidence_level = "very_low"? Rule R5: confidence ≤ 3 Answer: because confidence = 3.0 ← BASE FACT EXPLANATION OUTPUT: "High risk because high stress (8.5) combined with very low confidence (3.0)"

06 Optional Enhancement: Fuzzy Logic

File: ai/fuzzy_logic.py
Purpose: Provide a continuous risk score (0–10) instead of hard categories.

Why Fuzzy Logic?

Crisp rules say: stress = 7.9 is "high" but stress = 8.0 is "very_high". This boundary is arbitrary. Fuzzy logic allows partial membership in multiple categories simultaneously.
